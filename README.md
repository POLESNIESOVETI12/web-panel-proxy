<h1 align="center">WEB PANEL PROXY 2.5.0</h1>

<p align="center">WEB Proxy, MTProto, VLESS XHTTP, Hysteria2, OpenFlux и аккуратная панель управления для собственного VPS</p>

## Возможности

- Подписки и отдельные подключения с QR-кодами и готовыми конфигурациями.
- VLESS XHTTP и Hysteria2, включая прямые и CDN-подключения VLESS.
- Отдельные профили MTProto, Telegram Web Proxy и OpenFlux через Яндекс, Mail.ru или MAX для iOS и Android.
- Управление пользователями, ограничениями устройств, трафиком и состоянием служб.
- Объединение нескольких VPS в одну подписку через Node API token.
- Автоматическое определение страны ноды с отображением флага.
- Готовые HTML-заглушки и собственные страницы с HTML, CSS, JavaScript, SEO и аналитикой.
- Проверка обновлений и безопасное обновление с резервной копией настроек.

## Релиз 2.5.0

- Серверные подключения отделены от клиентов: один транспорт можно использовать для отдельных ключей и подписок.
- Добавлен редактор VLESS XHTTP с прямым маршрутом и CDN-провайдерами Yandex Cloud, VK Cloud, Beget, Selectel и собственным CDN.
- CDN Doctor проверяет DNS, TLS, источник, edge, методы, кеширование и локальный Xray; локальную часть WPP можно безопасно восстановить из интерфейса.
- Добавлены ограничения трафика и количества устройств, ноды, подписки, MTProto, Web Proxy, Hysteria2 и OpenFlux.
- Улучшены QR-коды, адаптивный интерфейс и окна создания и редактирования подключений.
- Новые XHTTP-ссылки используют правдоподобные статические пути к `index.html`, `config.json`, `segment0.ts` или `upload.m3u8`; прежние пути продолжают работать после обновления.
- Добавлено добровольное автоматическое обновление стабильных релизов с резервной копией, проверкой запуска и откатом.
- Убрана экспериментальная поддержка AWG, которая работала нестабильно на части серверов.

## Что нового в 2.4.4 CDN RC6

- Исправлена ситуация, когда AWG 2.0/3.1 показывал подключение, но трафик не выходил в интернет после запуска или перезагрузки UFW.
- Добавлен монитор сетевых правил: каждые 30 секунд он проверяет `ip_forward`, AWG NAT, маршрутизацию и принадлежащие панели правила UFW и восстанавливает только отсутствующие элементы.
- При создании AWG панель теперь проверяет маршрут клиента, masquerade и forwarding; нерабочий профиль не сохраняется как успешно созданный.
- Служба firewall запускается после UFW, а удаление панели корректно удаляет новый монитор.
- Выбор маршрута перенесён непосредственно в создание отдельного VLESS-подключения: **Напрямую** или **Через CDN**.
- Поддержаны профили Yandex Cloud CDN, VK Cloud CDN (экспериментально) и пользовательский CDN.
- Для каждого CDN-подключения отдельно сохраняются публичный домен, TLS SNI, HTTP Host и TLS fingerprint.
- Добавлен режим **GET-only** для CDN, которые не пропускают HTTP POST: данные XHTTP передаются в заголовках небольшими блоками.
- Прямые и CDN-подключения работают одновременно через разные внутренние XHTTP-маршруты; старые VLESS-профили остаются прямыми.
- Для CDN панель автоматически включает `packet-up`, обновляет серверный Xray и добавляет совместимый `extra` в ссылку и QR-код.
- Рекомендуемый режим `packet-up` снижает зависимость от поддержки долгих исходящих потоков CDN.
- AWG и Hysteria2 не отправляются через обычный HTTP CDN и продолжают работать напрямую.
- CDN применяется только к тем новым VLESS-профилям, для которых он выбран при создании.

Сначала создайте CDN-ресурс и TLS-сертификат у провайдера и направьте origin на домен панели. Затем откройте **Клиенты → Добавить клиента → Отдельное подключение → VLESS XHTTP**, выберите **Через CDN** и заполните параметры. Для GET-only нужен актуальный Xray-клиент с поддержкой расширенных параметров XHTTP.

## Основа сборки

Включены все исправления WEB PANEL PROXY 2.4.3 MAX RC5:

- Установка и обновление панели переведены на доступное GitHub-зеркало.
- Откат OpenFlux на версию без MAX блокируется, если на сервере уже есть MAX-профили.
- В службу OpenFlux для MAX теперь передаётся UID серверного аккаунта; без него транспорт `oneme` не мог установить связь.
- Повреждённое значение MAX UID в старом профиле больше не мешает создавать новые подключения.

- Основа сборки — стабильная версия 2.4.2 без изменений её UFW-логики.
- В OpenFlux добавлен транспорт MAX (`oneme`) через WebRTC.
- Для MAX используются два разных аккаунта: серверный принимает соединение, клиентский подключается к нему.
- QR-код и ссылка импорта автоматически передают клиентский токен и UID сервера.
- Серверный токен хранится в закрытом файле на VPS и не попадает в HTML, QR-код или ссылку импорта.
- Локация ноды определяется только по публичному IPv4 и сверяется по нескольким независимым источникам.
- Ошибка или лимит одного GeoIP-сервиса больше не перезаписывает сохранённую страну; ручной выбор администратора сохраняется.
- В установку, обновление и удаление добавлена закреплённая нижняя строка прогресса с процентом и текущим этапом.
- Неинтерактивная установка корректно принимает домен и ACME email из переменных окружения.
- Исправлено закрепление прогресса: вывод `apt`, `curl` и внутренних установщиков больше не затирает нижнюю строку.
- Все этапы установки теперь записывают одну и ту же версию пакета, без временного возврата к `2.4.2`.
- Исправлены гонки при одновременной проверке и установке версий компонентов.
- При ошибке запуска или ротации OpenFlux восстанавливает предыдущий ключ и останавливает нерабочую службу.
- UFW больше не забывает принадлежащее панели правило, если его удаление завершилось ошибкой.

## Требования

- Чистый VPS с Ubuntu 22.04+, Ubuntu 24.04+ или Debian 12+.
- Архитектура `x86_64` и доступ пользователя `root`.
- Домен или поддомен с A-записью на публичный IPv4 сервера.
- Свободные и открытые `80/tcp` и `443/tcp`.

Перед установкой убедитесь, что домен уже указывает на сервер. Дополнительные порты выбранных подключений панель покажет автоматически; их также нужно открыть во внешнем firewall личного кабинета VPS-провайдера.

## Быстрый старт

Подключитесь к серверу по SSH и перейдите в режим `root`:

```bash
sudo -i
```

### Установка

```bash
sudo -i bash -c 'curl -4fsSL "https://raw.githubusercontent.com/POLESNIESOVETI12/web-panel-proxy/v2.5.0/install.sh" -o /tmp/wpp-install.sh && bash /tmp/wpp-install.sh; code=$?; rm -f /tmp/wpp-install.sh; exit $code'
```

Команда станет доступна после публикации тега `v2.5.0` в GitHub. Установщик запросит домен, email для HTTPS-сертификата, логин и пароль панели. После установки он покажет адрес панели и данные для входа.

Локальная установка из ZIP:

```bash
apt-get -o DPkg::Lock::Timeout=600 install -y unzip && rm -rf /root/wpp-250-release && mkdir -p /root/wpp-250-release && unzip -q /root/WEB-PANEL-PROXY-V-2.5.0-GITHUB.zip -d /root/wpp-250-release && cd /root/wpp-250-release && chmod +x ./*.sh && bash ./install-final.sh
```

### После установки

1. Сохраните адрес панели, логин, пароль и Node API token в безопасном месте.
2. Откройте показанный HTTPS-адрес панели и создайте пользователя или отдельное подключение.
3. Скачайте конфигурацию, скопируйте ссылку либо отсканируйте QR-код подходящим клиентом.
4. Для удалённой ноды установите эту же версию WPP на втором VPS и добавьте её Node API token во вкладке **Ноды**.

### Обновление

```bash
/usr/local/sbin/web-panel-proxy-update
```

Обновление устанавливает последний стабильный релиз и сохраняет пользователей, ключи, настройки, адрес панели и HTML-заглушки.

### Удаление

```bash
/usr/local/sbin/web-panel-proxy-uninstall
```

> **Внимание:** удаление выполняется без дополнительного подтверждения и стирает пользователей, ключи, конфигурации, службы и сайт WEB PANEL PROXY.

## Сеть и порты

| Назначение | Порт |
|---|---:|
| HTTP, выпуск сертификата и перенаправление на HTTPS | `80/tcp` |
| HTTPS, панель и защищённые подключения | `443/tcp` |
| Hysteria2 по умолчанию | `8443/udp` |
| MTProto | выбранный порт, обычно `2399–2430/tcp` |

Caddy постоянно использует `80/tcp` и `443/tcp`. Не запускайте на этих портах другой веб-сервер. Если используется UFW, панель добавит свои правила, но firewall у VPS-провайдера необходимо настроить отдельно.

## Проверка состояния

Открыть консольное меню:

```bash
WPP
```

Проверить службы и последние сообщения панели:

```bash
systemctl --failed --no-pager
journalctl -u tproxy-panel.service -n 100 --no-pager
```

Проверить занятые порты:

```bash
ss -lntup
```

## Полезно знать

- Адрес панели, Node API token и ссылки подключений являются секретными — не публикуйте их.
- Перед обновлением автоматически создаётся резервная копия.
- Для OpenFlux требуется отдельная публичная ссылка на документ Яндекса или Mail.ru для каждого пользователя.
- QR-код OpenFlux содержит данные доступа. Не публикуйте его и удаляйте профиль при потере устройства.
- OpenFlux работает как экспериментальный IPv4/TCP-туннель; UDP и IPv6 через него не передаются.
- Резервные копии могут содержать пароли и ключи — не загружайте их в публичный репозиторий.
