<h1 align="center">WEB PANEL PROXY · 2.1.0</h1>

<p align="center">WEB Proxy, MTProto, VLESS XHTTP, Hysteria2 и панель управления для собственного VPS</p>

WEB PANEL PROXY 2.1.0 — стабильный установщик Telegram WEB Proxy, MTProto, Xray и веб-панели управления для собственного VPS.

Релиз включает прямые WEB Proxy и MTProto-подключения, VLESS XHTTP, Hysteria2, единые подписки, лимит устройств, живой дашборд, редактор HTML-заглушек с изолированным предпросмотром, светлую и графитово-синюю темы, безопасное обновление с откатом и полное удаление.

TCP-порт `80` остаётся свободным. Caddy выпускает и автоматически продлевает сертификат через ACME TLS-ALPN-01 на `443/tcp`; срок сертификата и ручная проверка доступны в меню `WPP`.

Панель создаёт отдельные WEB Proxy, MTProto, VLESS XHTTP и Hysteria2-подключения, показывает QR-код и готовую ссылку, управляет подписками и позволяет менять HTML главной страницы сайта.


## Возможности

- Установка одной командой на Ubuntu 22.04+ или Debian 12+ с безопасным продолжением после прерванной установки.
- Telegram WEB Proxy через HTTPS/443.
- VLESS XHTTP через TLS/443 и SNI домена, указанного при установке.
- Hysteria2 через QUIC/UDP 8443, TLS и тот же SNI-домен.
- Прямой MTProto для Telegram с отдельным секретом и автоматически выбранным TCP-портом.
- Закреплённая официальная сборка Xray с автоматической проверкой контрольной суммы.
- Дашборд с активностью каждого подключения, входящим, исходящим и общим трафиком.
- Накопительные per-user счётчики: nftables для WEB Proxy и штатный Stats API для Xray.
- Автоматическое обновление копии TLS-сертификата Xray после продления сертификата Caddy.
- Автоматическое продление HTTPS-сертификата через `443/tcp` без постоянного прослушивания `80/tcp`.
- Веб-панель по защищённому случайному адресу.
- Создание и удаление пользовательских подключений.
- Уникальный Secret и QR-код для каждого пользователя.
- Копирование готовой ссылки подключения для Telegram.
- Смена пароля администратора в панели.
- Закреплённая навигация и отдельная кнопка выхода.
- Обновление самой первой версии без панели с созданием учётной записи администратора.
- Полное удаление компонентов проекта отдельным скриптом.
- Консольное меню `WPP`: информация, обновление, проверка SSL, смена учётных данных, смена URL-пути и полное удаление.
- Единая подписка пользователя: VLESS XHTTP и/или Hysteria2, одна ссылка и QR-код.
- Лимит регистрации 1–20 HWID, отдельные ключи устройств, отзыв доступа, отключение и ротация подписки. Значение 0 отключает HWID-привязку.
- Черновик HTML, предпросмотр «компьютер/телефон» и отдельная публикация.

## Требования

- VPS с Ubuntu 22.04+ или Debian 12+.
- Домен или поддомен с A-записью, направленной на IPv4 вашего VPS.
- Открытый TCP-порт `443`; для Hysteria2 нужен `8443/udp`, а каждому прямому MTProto назначается отдельный TCP-порт из диапазона `2399–2430`. Порт `80/tcp` WEB PANEL PROXY не использует и не требует.
- Доступ к серверу от пользователя `root`.
- Если Caddy уже установлен, его бинарник, служба и посторонние сайты сохраняются; установщик добавляет или обновляет только блок выбранного домена WEB Proxy.
- Порт `443/tcp` занят Caddy постоянно, потому что через него работают сайт, панель, WEB Proxy, VLESS и проверка TLS-сертификата. Порт `80/tcp` остаётся свободным для другой программы.
- Установщик сам добавляет локальные правила `nftables` и UFW для Hysteria2 и MTProto. Firewall в личном кабинете VPS-провайдера скрипт изменить не может: там разрешите `8443/udp` и назначенный панелью MTProto TCP-порт либо диапазон `2399–2430/tcp`.

## Установка одной командой из GitHub

После публикации неизменяемого тега `v2.1.0` выполните на чистом VPS от `root`:

```bash
apt-get -o DPkg::Lock::Timeout=600 update && apt-get -o DPkg::Lock::Timeout=600 install -y curl ca-certificates && bash -c "$(curl -fsSL --proto '=https' --tlsv1.2 https://raw.githubusercontent.com/POLESNIESOVETI12/web-panel-proxy/v2.1.0/install.sh)"
```

1. Домен, например `proxy.example.com`.
2. Email для выпуска HTTPS-сертификата.
3. Логин и уникальный пароль администратора панели длиной не менее 8 символов.

В конце установки будут выведены адрес панели, логин и пароль. Сохраните эти данные в безопасном месте.

После установки в терминале VPS доступно меню:

```bash
WPP
```

Также можно использовать команду `wpp`. В меню отображаются URL панели, логин, версия, срок SSL, состояние TCP/80 и служб; можно запустить обновление или удаление, проверить SSL, сменить логин с паролем и изменить приватный URL-путь панели. Пароль намеренно не хранится в открытом виде, поэтому раздел «Информация» его не показывает — при необходимости задайте новый пароль через соответствующий пункт.

Повторный запуск установщика не требует предварительно удалять Caddy, MTProxy или relay: совместимые работающие компоненты переиспользуются, недостающие устанавливаются. Для уже настроенной панели сохраняются пользователи, пароль, приватный адрес и HTML-заглушка.

## Работа с панелью

Откройте URL панели, который показал установщик, и войдите с указанными данными.

### Пользователи

Во вкладке **Пользователи**:

1. Нажмите **Добавить клиента** и введите имя.
2. Выберите одну подписку или отдельную ссылку, затем отметьте нужные протоколы понятными карточками.
3. Для подписки выберите протоколы и лимит HWID. Нажмите **Создать клиента**.
4. Скопируйте ссылку или откройте **QR** в карточке пользователя.
5. Управление подпиской находится в **Настройки и устройства**, отдельным подключением — в **Параметры подключения**.

Поиск по имени и фильтры «Все / Подписки / Отдельные ссылки» помогают найти нужную карточку. Старые отдельные ссылки сохранены и не превращаются в новые подписки автоматически.

Основной Secret установки удалить нельзя.

### Подписки и лимит устройств

1. Откройте **Пользователи → Добавить клиента**, выберите **Одна подписка**, задайте имя и отметьте нужные протоколы.
2. Укажите максимум устройств, например 2, и создайте подписку.
3. Скопируйте единую ссылку или её QR. Добавьте ссылку как **подписку** в клиент, передающий заголовок `X-HWID` (например, поддерживающая его версия Happ).
4. При первом запросе с новым HWID создаются отдельные ключи выбранных протоколов. Повторное обновление с тем же HWID возвращает прежние ключи и не занимает ещё одно место.
5. Когда лимит исчерпан, новый HWID получает отказ. В «Настройки и устройства» можно отозвать устройство: его ключи удаляются, место освобождается, прежний HWID остаётся заблокированным. «Разрешить» снимает блокировку, но при следующем импорте создаются новые ключи.
6. «Сменить ссылку» отзывает старую ссылку и все её ключи. После этого пользователю нужно импортировать новую подписку.

**Что именно ограничивается:** число зарегистрированных идентификаторов клиента, не число TCP-соединений, IP-адресов или физически проверенных устройств. HWID можно подделать, а выданный ключ — скопировать в другой клиент. Это контроль регистрации и отзыва, **не защита от намеренного совместного использования ключа**. Строгий аппаратный лимит стандартными ссылками VLESS/Hysteria2 не обеспечивается.

При лимите 0 подписка работает без HWID и выдаёт всем запросам один общий набор ключей. Переход между 0 и ненулевым лимитом отзывает старые ключи. Уменьшить лимит ниже числа зарегистрированных устройств нельзя: сначала отзовите лишние.

Открытие ссылки обычным браузером показывает инструкцию, но не регистрирует устройство. Ошибка 403 при импорте означает отсутствующий HWID, исчерпанный лимит или отозванное устройство. Подписки обновляются клиентом периодически; после изменений обновите их вручную.

WEB Proxy остаётся отдельной Telegram-ссылкой: HWID-привязка на него не распространяется. Существующие отдельные пользователи не объединяются автоматически и сохраняют ID/ключи. Подписка отображается одной карточкой в «Пользователи» и на дашборде. Внутренние профили устройств не дублируют карточки.

Первая регистрация, отзыв и другие изменения ключей применяют конфигурацию Xray и могут кратковременно прервать соответствующие соединения. Обычное обновление уже зарегистрированного устройства не перезапускает службы. Счётчик подписки суммирует её профили, включая отозванные; время обновления устройства — это запрос подписки, **не статус онлайн**. Предусмотрены пределы 64 подписки и 256 одновременно созданных профилей подписок на сервер.

### Дашборд

Дашборд показывает CPU, RAM, подкачку и диск VPS, состояния Xray/Caddy/relay/панели, время работы VPS и Xray, память и задачи Xray, среднюю нагрузку, количество пользователей и подписок. Подписка отображается одним пользователем с суммарным трафиком её профилей, в том числе ранее отозванных.

График скорости отправки/получения строится по реальным замерам трафика **прокси**, а не всего сетевого интерфейса VPS. Доступны интервалы 1, 6 и 24 часа; измерения собираются примерно каждые 10 секунд. История хранится на сервере до 24 часов и переживает перезапуск панели. После установки подождите несколько замеров для появления линии. Старые данные не восстанавливаются задним числом; разрывы измерений не интерполируются. Устаревшие показатели помечаются как недоступные.

«Передаёт трафик» означает передачу данных за последние 90 секунд. Это **не число подключённых устройств онлайн**. Отозванные профили сохраняют накопленный трафик, но не учитываются как активные. Дашборд получает свежие данные каждые 5 секунд и меняет только обновившиеся блоки; кнопка **Обновить** запускает внеочередной запрос, не обновляя программу.

### Темы и обновление из панели

Переключатель в верхней строке панели и на странице входа меняет тёмную/светлую тему. Выбор сохраняется в текущем браузере. На узком экране навигация адаптируется, карточки идут в одну колонку.

Кнопка **Проверить обновления** проверяет стабильные теги вида `vN.N.N` в официальном репозитории проекта. Если есть более новая версия, появляется **Обновить** с подтверждением. Это не загрузка ZIP с диска VPS: локальную тестовую сборку устанавливайте командой `update.sh --local`. До публикации нового стабильного тега кнопка может сообщать, что обновлений нет.

Обновление запускается отдельной root-службой systemd и продолжает работать при перезапуске панели. Сохраняются резервная копия и результат; прокси-соединения могут кратковременно прерваться. При ошибке проверьте SSH: `journalctl -u web-panel-proxy-web-update.service --no-pager -n 80`. Подробный журнал — `/var/lib/web-panel-proxy-update/update.log` (доступ root; может содержать секретные данные, не публикуйте целиком). URL источника и команда фиксированы, произвольную shell-команду браузер передать не может.

WEB Proxy и MTProto импортируются в Telegram. VLESS использует домен установки как SNI и `443/tcp`; Hysteria2 — тот же TLS-домен и `8443/udp`.

Точные пользовательские счётчики доступны для WEB Proxy, MTProto, VLESS и Hysteria2.

### Настройки

Во вкладке **Настройки** можно:

- открыть один из HTML-пресетов в черновике;
- вставить свой HTML-код главной страницы;
- сохранить черновик без изменения рабочего сайта;
- открыть «Предпросмотр» в отдельном модальном окне и переключить «Компьютер»/«Телефон»; закрытие окна останавливает выполнение его скриптов;
- отдельно нажать «Опубликовать на сайте» для замены главной страницы;
- сменить пароль администратора.

Боковая навигация на компьютере остаётся на месте при прокрутке содержимого. Кнопка **Выйти** завершает текущую сессию панели.

Перед заменой HTML сохраняется резервная копия. Панель выносит встроенные CSS, JavaScript и атрибуты `style` в локальные файлы с уникальными именами, поэтому браузер не смешивает кэш разных пресетов. Доступность файлов проверяется через relay после перезапуска.

Предпросмотр использует тот же преобразователь CSS/JS, но не пишет публичные файлы и не перезапускает службы. Он работает в `iframe sandbox` без доступа к DOM/куки панели, сетевым запросам, формам и сетевой навигации. Скрипты внутри HTML работают; внешние ресурсы — нет. Черновик хранится приватно на сервере и переживает перезапуск. Пресет заменяет текущий черновик, но не опубликованный сайт. При ошибке публикации черновик остаётся доступным для исправления. Предпросмотр не гарантирует идентичного результата во всех браузерах и с любым сторонним HTML: проверяйте страницу после публикации.

### Своя HTML-заглушка

Вставляйте полный HTML одним файлом: стили внутри `<style>`, атрибуты `style="..."` и скрипты внутри `<script>` панель автоматически подготовит для WEB Proxy. Не используйте CDN, внешние шрифты/библиотеки, внешние изображения и inline-обработчики вроде `onclick="..."`: relay намеренно блокирует сторонние ресурсы и небезопасные обработчики. Все нужные стили и скрипты должны быть внутри вставленного HTML, а события подключены через `addEventListener`.

## Обновление этой сборкой с сохранением данных

Загрузите ZIP в `/root` и выполните от root:

```bash
apt-get -o DPkg::Lock::Timeout=600 update && apt-get -o DPkg::Lock::Timeout=600 install -y unzip
WPP_DIR=$(mktemp -d /root/wpp-update.XXXXXX) && unzip -q /root/WEB-PANEL-PROXY-V-2.1.0.zip -d "$WPP_DIR" && cd "$WPP_DIR" && bash ./update.sh --local
```

Из уже распакованной папки нужна одна команда: `bash ./update.sh --local`. Флаг `--local` устанавливает именно содержимое этого ZIP. Без него обновление и меню `WPP` ищут последний стабильный релиз на GitHub.

Обновление меняет файлы панели, но сохраняет пользователей, секреты, пароль администратора, приватный адрес панели и HTML-заглушку сайта. Перед началом автоматически создаётся резервная копия в `/root/web-panel-proxy-update-backup-ДАТА-ВРЕМЯ`. Relay сначала проходит тесты и проверку конфигурации; при ошибке предыдущий бинарник и состояние панели восстанавливаются автоматически.

На время обновления веб-панель недоступна; службы прокси перезапускаются на соответствующем этапе. Резервная копия содержит секреты — не публикуйте её. Удалять рабочую установку перед обновлением не нужно.

После публикации релиза обновление до последнего стабильного тега запускается одной командой:

```bash
sudo /usr/local/sbin/web-panel-proxy-update
```

Если обнаружена самая первая версия WEB Proxy без панели, обновление извлекает существующие домен и основной Secret, затем предлагает создать логин и пароль администратора. Пароль вводится один раз и должен содержать минимум 8 символов; после этого создаются панель и её приватный адрес.

## Удаление одной командой

После установки доступна локальная команда. **Она удаляет пользователей, подписки, ключи, черновик и сайт без дополнительного подтверждения**:

```bash
sudo /usr/local/sbin/web-panel-proxy-uninstall
```

Скрипт не просит вводить подтверждение. Он останавливает и удаляет службы, правила firewall, конфигурации, Secrets, Xray, панель, сайт и компоненты WEB PANEL PROXY 2.1.0. Если после установки в Caddy были добавлены другие сайты, удаляется только блок домена WEB PANEL PROXY, а остальные сайты и Caddy сохраняются.

## Безопасность

- Backend- и статистические порты закрываются постоянной службой `web-proxy-panel-firewall.service`.
- VLESS слушает только локальный адрес и доступен снаружи исключительно через Caddy и TLS/443.
- Hysteria2 использует отдельный UDP/8443, собственную TLS-проверку и сертификат домена установки.
- Служба firewall повторно применяет правила после запуска или перезапуска `nftables` и стартует раньше пользовательских proxy-служб.
- После 8 неудачных попыток входа с одного адреса авторизация временно блокируется.
- Сессии подписываются HMAC-SHA256; смена пароля завершает все ранее выданные сессии.
- Xray использует закреплённую версию и проверяемую SHA-256, исходники relay — закреплённый commit.
- Xray `26.7.28` загружается из официального репозитория и нужен текущей реализации Hysteria2, но upstream помечает этот выпуск как pre-release. Версия закреплена и не обновляется автоматически без проверки совместимости.
- Ссылка подписки — секрет доступа. Передавайте её только нужному пользователю, не публикуйте в логах/скриншотах. HTTP-ответы подписки не кэшируются; токен и HWID не передаются в аргументах процессов.
- В базе хранится хеш HWID с привязкой к подписке, не исходный идентификатор. Лимит не является надёжной аппаратной привязкой.
- Не публикуйте данные `/etc/web-proxy-panel`, `/var/lib/tproxy-panel`, TLS-ключи и резервные копии.
- Установщик и панель требуют пароль длиной не менее 8 символов. Для публичного сервера используйте длинный уникальный пароль и менеджер паролей.
- Во внешнем firewall провайдера разрешите `22/tcp`, `443/tcp`; добавьте `8443/udp` для Hysteria2 и назначенные панелью TCP-порты MTProto. Открывать `80/tcp` для WPP не требуется.
